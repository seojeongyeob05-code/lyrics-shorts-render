**한 일: 많은 파일 업로드 버그 수정 (나눠서 올리기)**

- 버그: 음악 폴더를 통째로 끌어다 놓아 파일이 100개를 넘으면 서버가 요청 전체를 거절해서 한 곡도 올라가지 않았고, 오류도 영어("Too many files")로 나왔습니다. 또 200MB가 넘는 파일이 하나라도 섞이면 같이 올린 다른 파일까지 모두 실패했습니다.
- 수정: 브라우저가 파일을 20개·200MB 단위로 나눠 차례로 보냅니다.

  - 최대 크기를 넘는 파일은 미리 빼고 "200MB가 넘는 파일 N개 건너뜀"으로 알려 줍니다. 서버가 상태 API로 한도를 알려 줍니다.

  - 업로드 중에 또 올리려고 하면 끝난 뒤 다시 하라고 안내합니다.
- 서버: 파일 수 초과 오류를 한국어로 안내합니다. 파일 수 한도는 설정 값(`maxUploadFiles`)으로 뺐습니다.

## 2026-11-06

**한 일: .lrc 가사 파일 자동 짝짓기**

- 업로드할 때 `.lrc` 파일도 받습니다.
  - 음원과 함께 올리면 이름이 같은 곡에 가사로 붙습니다. 예: `봄날의 노래.mp3` + `봄날의 노래.lrc`. 대소문자, 맥의 자모 분리 파일명도 같은 이름으로 봅니다.
  - `.lrc`만 따로 올리면 제목이 같은 기존 곡에 붙습니다. 같은 제목의 곡이 여럿이면 어느 곡인지 알 수 없어 건너뜁니다.
  - 이미 있는 곡(중복)과 함께 올린 `.lrc`는 기존 곡에 붙습니다.
  - 파일로 직접 올린 가사가 음원 태그의 가사보다 우선합니다.
- 한국어 `.lrc` 파일에 흔한 EUC-KR(CP949) 인코딩도 읽습니다 (UTF-8이 아니면 EUC-KR로 해석).
- 업로드 결과 알림에 "가사 N개를 연결했습니다", "짝을 못 찾은 가사 N개 건너뜀"이 표시되고, 지금 재생 중인 곡에 가사가 붙으면 가사 패널이 바로 바뀝니다.
- 가사 파일은 읽은 뒤 서버 디스크에서 지웁니다 (가사는 DB에 저장).
- 테스트 3개 추가 (함께 올리기, .lrc만 올리기 + EUC-KR + 짝 없음·빈 파일, 인코딩 판별. 전체 29개 통과). 브라우저에서 재생 중인 곡의 가사가 업로드 직후 패널에 나타나는 것을 확인했습니다.

## 2026-11-03

**한 일: 중복 업로드 감지**

- 업로드할 때 파일 내용의 SHA-256 해시를 비교해서, 이미 있는 곡이면 저장하지 않고 건너뜁니다. 파일 이름이 달라도 내용이 같으면 중복으로 봅니다. 한 번에 올린 파일들끼리 겹쳐도 하나만 남습니다.

- DB에 `hash` 컬럼을 추가했습니다. 서버를 켤 때 예전 DB에는 컬럼을 자동으로 붙이고(기존 데이터는 그대로), 이전에 올린 곡의 해시는 백그라운드에서 계산합니다.
- 테스트 2개를 추가했습니다: 중복 업로드(다른 이름, 같은 요청 안의 중복, 디스크에 파일이 남지 않는지)와 예전 DB 마이그레이션·해시 채우기 (전체 17개 통과). 어제까지 쓰던 실제 데이터로 서버를 켜서 마이그레이션이 되는지, 브라우저에서 같은 파일을 다시 올리면 건너뛰는지도 확인했습니다.

**참고**

- 버그 수정: macOS에서 올린 한글 파일명은 자모가 분리된(NFD) 형태라 화면에는 정상으로 보여도 검색·정렬이 안 됐습니다. 업로드할 때 파일명과 태그(제목·아티스트·앨범)를 NFC로 합쳐서 저장합니다.
  - 이미 올라가 있는 곡은 DB에 그대로 남지만, 검색 쪽에서도 NFC로 맞춰 비교하므로 검색은 됩니다.
- 테스트: 검색 단위 테스트 5개와 NFD 업로드 테스트 1개를 추가했습니다 (전체 12개 통과). 브라우저에서도 초성 검색, 검색 결과 재생, Esc 초기화를 확인했습니다.
