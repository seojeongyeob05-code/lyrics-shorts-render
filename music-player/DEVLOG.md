## 2026-11-06

**한 일: .lrc 가사 파일 자동 짝짓기**

- 업로드할 때 `.lrc` 파일도 받습니다.
  - 음원과 함께 올리면 이름이 같은 곡에 가사로 붙습니다. 예: `봄날의 노래.mp3` + `봄날의 노래.lrc`. 대소문자, 맥의 자모 분리 파일명도 같은 이름으로 봅니다.
  - `.lrc`만 따로 올리면 제목이 같은 기존 곡에 붙습니다. 같은 제목의 곡이 여럿이면 어느 곡인지 알 수 없어 건너뜁니다.
  - 이미 있는 곡(중복)과 함께 올린 `.lrc`는 기존 곡에 붙습니다.
  - 파일로 직접 올린 가사가 음원 태그의 가사보다 우선합니다.
- 한국어 `.lrc` 파일에 흔한 EUC-KR(CP949) 인코딩도 읽습니다 (UTF-8이 아니면 EUC-KR로 해석).
- 업로드 결과 알림에 "가사 N개를 연결했습니다", "짝을 못 찾은 가사 N개 건너뜀"이 표시되고, 지금 재생 중인 곡에 가사가 붙으면 가사 패널이 바로 바뀝니다.
- 가사 파일은 읽은 뒤 서버 디스크에서 지웁니다 (가사는 DB에 저장).
- 테스트 3개 추가 (함께 올리기, .lrc만 올리기 + EUC-KR + 짝 없음·빈 파일, 인코딩 판별. 전체 29개 통과). 브라우저에서 재생 중인 곡의 가사가 업로드 직후 패널에 나타나는 것을 확인했습니다.

## 2026-11-05

**한 일: 가사 보기 (싱크 가사 .lrc 지원)**

- 플레이어 오른쪽 아래에 가사 버튼을 추가했습니다. 가사 패널은 재생 대기열과 같은 자리에 열리고, 둘 중 하나만 열립니다. 열어 둔 패널은 새로고침해도 유지됩니다.
  - 싱크 가사(`[00:12.34]가사` 형식)는 지금 부르는 줄이 강조되고 가운데로 자동 스크롤됩니다. 줄을 누르면 그 부분부터 재생됩니다.
  - 시간 표시가 없는 일반 가사는 그대로 보여 줍니다.
- 가사 넣는 방법
  - 곡의 ⋯ 메뉴 "가사 추가/편집…" 또는 가사 패널의 "가사 편집"에서 붙여 넣거나 `.lrc` 파일을 불러옵니다. 비우고 확인하면 지워집니다.
  - 음원 파일 태그에 가사가 들어 있으면(예: FLAC의 LYRICS) 업로드할 때 자동으로 가져옵니다.
- 서버: `lyrics` 컬럼 추가(기존 DB에는 켤 때 자동으로 붙음), `GET/PUT /api/tracks/:id/lyrics`. LRC의 `[offset:]`, 한 줄에 여러 시간, 정보 태그(`[ti:]` 등)도 처리합니다.
- 테스트 8개 추가 (가사 파서, 태그 변환, 가사 API, 가사가 들어 있는 실제 FLAC 업로드. 전체 26개 통과). 브라우저에서 강조가 재생을 따라가는지, 줄 클릭 이동, 일반 가사, 지우기, 패널 전환과 새로고침 후 유지를 확인했습니다. 어제까지 쓰던 데이터로 서버를 켜서 DB 마이그레이션도 확인했습니다.

**참고**

- 대부분의 MP3 파일은 가사를 USLT 태그에 일반 가사로만 담고 있어서, 싱크 가사가 필요하면 `.lrc`를 따로 넣어야 합니다.

## 2026-11-04

**한 일: 곡 정보 수정**

- 곡의 ⋯ 메뉴에 "곡 정보 수정…"을 추가했습니다. 제목·아티스트·앨범을 고칠 수 있고, 지금 값이 미리 채워져 있습니다. 태그가 없거나 잘못된 곡을 바로잡는 용도입니다.
  - 제목은 비울 수 없고, 아티스트·앨범은 비우면 "알 수 없는 아티스트"/빈칸으로 돌아갑니다. 각각 200자까지 입력할 수 있습니다.
  - 고친 정보는 곡 목록, 아래 플레이어, 재생 대기열, OS 미디어 컨트롤에 바로 반영됩니다.
  - DB의 곡 정보만 바꾸고 원본 음원 파일의 태그는 건드리지 않습니다.
- 버그 예방: OS 미디어 컨트롤 정보가 곡이 바뀔 때만 갱신되던 것을, 같은 곡의 정보가 바뀌어도 갱신되도록 고쳤습니다.
- 서버에 `PATCH /api/tracks/:id`를 추가하고 테스트를 1개 추가했습니다 (부분 수정, 빈 값, 잘못된 값·길이, 없는 곡 처리. 전체 18개 통과). 브라우저에서 수정·취소·빈 제목 막기와 화면 곳곳에 반영되는지 확인했습니다.

## 2026-11-03

**한 일: 중복 업로드 감지**

- 업로드할 때 파일 내용의 SHA-256 해시를 비교해서, 이미 있는 곡이면 저장하지 않고 건너뜁니다. 파일 이름이 달라도 내용이 같으면 중복으로 봅니다. 한 번에 올린 파일들끼리 겹쳐도 하나만 남습니다.
- 업로드 결과 알림에 "이미 있는 곡 N개 건너뜀"이 표시됩니다. 새 곡이 하나도 없으면 "새로 추가된 곡이 없습니다"라고 나옵니다.
- DB에 `hash` 컬럼을 추가했습니다. 서버를 켤 때 예전 DB에는 컬럼을 자동으로 붙이고(기존 데이터는 그대로), 이전에 올린 곡의 해시는 백그라운드에서 계산합니다.
- 테스트 2개를 추가했습니다: 중복 업로드(다른 이름, 같은 요청 안의 중복, 디스크에 파일이 남지 않는지)와 예전 DB 마이그레이션·해시 채우기 (전체 17개 통과). 어제까지 쓰던 실제 데이터로 서버를 켜서 마이그레이션이 되는지, 브라우저에서 같은 파일을 다시 올리면 건너뛰는지도 확인했습니다.

**참고**

- 같은 곡이라도 비트레이트나 형식이 다른 파일(예: MP3와 FLAC)은 내용이 달라 중복으로 잡히지 않습니다.
- 곡이 아주 많으면 처음 서버를 켤 때 해시 계산에 시간이 걸릴 수 있습니다. 백그라운드에서 돌기 때문에 그동안에도 사용할 수 있습니다.

## 2026-11-01

**한 일: 곡 검색 추가, macOS 한글 파일명 버그 수정**

- 라이브러리와 플레이리스트 화면 위에 검색창을 추가했습니다. 제목·아티스트·앨범에서 찾고, 대소문자와 띄어쓰기는 무시합니다.
  - 초성 검색: `ㅂㄴ`으로 "봄날의 노래"를 찾을 수 있습니다.
  - `/` 키로 검색창에 바로 들어가고, `Esc`로 검색어를 지웁니다.
  - 검색 결과에서 곡을 누르거나 "재생"을 누르면 검색 결과만 재생 목록이 됩니다.
  - 검색 중에는 플레이리스트 드래그 정렬을 막습니다 (보이는 순서와 실제 순서가 달라서).
- 버그 수정: macOS에서 올린 한글 파일명은 자모가 분리된(NFD) 형태라 화면에는 정상으로 보여도 검색·정렬이 안 됐습니다. 업로드할 때 파일명과 태그(제목·아티스트·앨범)를 NFC로 합쳐서 저장합니다.
  - 이미 올라가 있는 곡은 DB에 그대로 남지만, 검색 쪽에서도 NFC로 맞춰 비교하므로 검색은 됩니다.
- 테스트: 검색 단위 테스트 5개와 NFD 업로드 테스트 1개를 추가했습니다 (전체 12개 통과). 브라우저에서도 초성 검색, 검색 결과 재생, Esc 초기화를 확인했습니다.
